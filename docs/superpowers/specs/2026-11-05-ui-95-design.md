Deliver the user's Agent 6 brief on `feature/95-ui`, from main
`4ad205b84d1852ec7ed33cabd70fdadbe2f9d5c5`. Improve the existing Swedish,
monochrome interface for overview, invoices, payment evidence, review and bank
onboarding. Deliver a PR with current browser evidence, accessible controls and
honest blocked-flow reporting. The user authorized implementation and a PR;

## Chosen approach

Implementation choice: retain the current React/Sites components and API
contracts, introduce a small final stylesheet and targeted component fixes.
A separate replacement frontend would duplicate already-tested evidence and
company boundaries. CSS-only changes would leave false empty-state actions,
hardcoded identity and failed-read ambiguity unresolved.

## Presentation rules

- Use white surfaces, near-black text, subtle grey backgrounds and borders.
  Text/icons/labels carry status meaning; colour alone never conveys evidence.
- One primary action per task area; unrelated import/create buttons do not
  appear in settings, history, bank connection or review headers.
- Preserve `Inbetalt`, `Kvar att få`, `Att betala`, `Behöver granskas` and the
  primary `Kontrollera alla betalningar` action. Missing data stays unknown.
- Invoice numbers and references remain strings, including leading zeroes.
  Intended invoice reference, formal OCR and observed bank reference retain
  their existing classifications. A customer is not substituted for a payer.
- Display verified payer only through the existing evidence projection.
  Unverified allocations, source failures and absent Bankgiro data stay visible.
- Keep summary reading short; detailed provenance remains available in place.
- Native labelled controls, visible keyboard focus, 44 px main control targets,
  readable text, reduced motion and reflow down to 320 CSS px.
- No backend, schema, provider, allocation, balance, reconciliation or
  authorization change; no package or lockfile change planned.

## Acceptance and evidence

Use actual product components, real React and emitted production CSS against
strictly local synthetic HTTP fixtures. Record source/build hashes and capture
desktop (1440), tablet (768/1024), mobile (390) and 320 px reflow evidence.
Exercise navigation, invoice search/filter/reset/detail, review selection/back,
bank evidence details, company and bank choices, unavailable/empty/loading
states and keyboard modal behavior. Confirm rendering/filtering does not
perform financial writes. Run relevant regression tests and the repository's
required syntax, types, test, audit and build gates.

Browser acceptance is distinct from an authenticated live bank/BankID journey,
physical devices and assistive-technology testing. Automated checks do not
certify full WCAG conformance. The existing scorecard's production-evidence
gate remains binding; do not label an unverified 9.5/10 as achieved.
