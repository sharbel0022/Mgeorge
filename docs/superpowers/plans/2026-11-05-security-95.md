# Security 9.5 target — implementation plan

> **For agentic workers:** Use the relevant execution/review skills. Work only in
> the assigned files; coordinate shared modules before changing them.

**Goal:** Deliver proven security/reliability improvements and an honest release
risk assessment in a PR on `feature/95-security`.

**Architecture:** Preserve Node/SQLite and Sites/D1/R2. Add bounded ingress and
persistent login admission to existing request boundaries. Harden recovery and
CI only where reproductions establish a concrete gap.

**Tech stack:** Node.js, TypeScript, SQLite, D1, R2, Web Streams, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-05-security-95-design.md`.

## Global constraints

- Synthetic isolated tests only; no real bank/provider probes or production writes.
- No secrets or customer originals in logs, tests, reports, or commits.
- Only push the requested branch and create a PR; no merge or deployment.
- Preserve tenant, membership, lease, OAuth, original-integrity, and economic rules.
- A successful build/test run is not a production recovery or GDPR certification.

## Review focus

- Missing, false or malformed Content-Length; multibyte bodies and stream failures.
- A cloned body used by authorization must share the same byte budget.
- Login windows survive a process restart and atomic competing reservations.
- Tampered/corrupt backup content and changed membership during recovery.
- CI/test helpers must not silently reuse live credentials or leak error payloads.
