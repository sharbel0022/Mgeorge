# Bankgiro evidence implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` with independent parallel audits and a final independent review. Steps use checkbox syntax for tracking.

**Goal:** Preserve actual Bankgiro identity and expose a traceable, correctly qualified evidence chain to the invoice.

**Architecture:** Extend the existing parsers, verification projection and owner-scoped read API. Reuse existing intake, originals, company boundaries and financial controls.

**Tech Stack:** Node.js, shared JavaScript, TypeScript, SQLite/D1/R2, node:test.

**Spec:** `docs/superpowers/specs/2026-11-05-bankgiro-95-design.md`.

## Global constraints

- Own branch `feature/95-bankgiro`, PR to `main`; no merge/deploy/production financial mutations.
- Actual OCR/payer fields only; preserve `0599` exactly.
- Only synthetic test originals; private bank originals never enter git.
- Keep existing provider scopes, contracts, originals, idempotency and source/consent fences.
- Root and Sites changes receive the applicable full verification gates.

## Review focus

1. A retained but corrupt or absent original must not yield a passed reference check.
2. Conflicting bank fields must not be silently preferred or truncated into a valid identifier.
3. Report history must not join another owner or infer an invoice from matching amount/date.
4. Partial or oversized history must never claim a complete evidence chain.
5. Provider authority and aggregate completeness must remain independent of a valid SHA-256.
